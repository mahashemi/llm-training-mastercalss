# Course Operating Manual

## For an individual learner

Follow:
START_HERE → lectures → notebooks → textbook → projects → paper reproduction → final Model Program Dossier.

Do not skip the baseline and failure-analysis steps.

## For a university course

A useful semester structure is:

| Phase | Focus | Evidence |
|---|---|---|
| 1 | language-model foundations | tiny LM |
| 2 | Transformer implementation | architecture lab |
| 3 | data engineering | dataset card |
| 4 | training systems | resource report |
| 5 | post-training | SFT/PEFT comparison |
| 6 | evaluation | benchmark report |
| 7 | systems | serving report |
| 8 | research | reproduction/ablation |
| 9 | program design | proposal |
| 10 | capstone | defense |

## For an organization

Adopt the repository as:
- onboarding curriculum;
- model-training runbook;
- experiment documentation standard;
- research reproduction library;
- proposal template library.

## For a national program

Use the curriculum to build capability in four layers:

1. **People** — researchers, data engineers, systems engineers, language/domain experts, evaluators, program managers.
2. **Data** — lawful, representative, versioned, auditable corpora.
3. **Compute** — measured infrastructure with realistic utilization and recovery.
4. **Evidence** — evaluation, publications, reproducible experiments, and milestone artifacts.

## Graduation criterion

A learner is ready for independent model work when they can:

- train a small model from scratch;
- diagnose its failures;
- adapt an open model;
- justify the adaptation method;
- evaluate target and retained capabilities;
- calculate resources;
- design a distributed scaling plan;
- create a reproducible experiment;
- prepare a proposal with budget and kill criteria.

The capstone should be defended orally, not only submitted.
